# 🏗️ SYSTEM ARCHITECTURE & EVOLUTION LIFECYCLE
> **whatImSupposedto-Didit 프로젝트의 통합 데이터 흐름 및 8단계 무중단 제품 진화 모델**

본 문서는 서비스 프로덕션의 코어 엔진인 비정형 마크다운 파이프라인이 MVP(Minimum Viable Product) 단계에서 출발하여, 실전 비즈니스 가용성과 철벽 장애 복구 능력을 갖춘 엔터프라이즈 레벨로 진화하는 아키텍처 모델을 정의합니다.

---

## 🧭 1. 엔드투엔드 데이터 흐름 레이어 (End-to-End Data Pipeline)

애플리케이션에 투입된 비정형 `.md` 텍스트 컨텍스트는 총 4개의 핵심 시스템 레이어를 관통하며 가치 데이터로 가공됩니다.

```text
[비정형 마크다운 자산 입력]
  │   - 목표 정의 파일 (*_target.md)
  │   - 대화록 스트림 (*_script.md)
  ▼
┌─────────────────────────────────────────────────────────┐
│ 1. CORE PARSING LAYER (코어 파싱 및 격리)               │
│    - mdStaticParser: Front Matter 및 특화 토큰 분리      │
│    - scriptSplitter: 정규식 기반 특정 유저 발화 격리     │
└───────────────────────────┬─────────────────────────────┘
                            │ (JSON 구조화 데이터 이관)
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 2. INTELLIGENCE & EVALUATION LAYER (분석 및 판정)        │
│    - aiContrastEngine: GPT-4o Structured Outputs 가동   │
│    - purpleKpiEngine: Substring 명확 성취 로그 산출     │
└───────────────────────────┬─────────────────────────────┘
                            │ (4단 처방 및 KPI 리포트 완료)
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 3. PERSISTENCE & GATEWAY LAYER (영속성 및 보안)          │
│    - Supabase PostgreSQL: 파싱 로그 및 설정 동기화       │
│    - Row Level Security: 타인 표현 합법적 스틸(Steal) 보안│
└───────────────────────────┬─────────────────────────────┘
                            │ (장애 발생 혹은 릴리스 교체 시)
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 4. FAULT-TOLERANT & OPERATION LAYER (안정 제어 및 수호) │
│    - Circuit Breaker: 5초 지연 시 IndexedDB 대피 라우팅 │
│    - Feature Flag: 실시간 핫픽스 컴포넌트 온/오프 제어   │
│    - Rollback Handler: 8초 타이머 기반 강제 복구 트랜잭션 │
└─────────────────────────────────────────────────────────┘
```

## 🔄 2. 8단계 제품 진화 아키텍처 (The 8-Phase Evolution Model)

본 시스템은 정적 유닛 단위의 동작 보장에서부터 클라우드 무인 자동화, 나아가 실시간 다운타임 제로 제어 단계까지 유기적인 가드레일을 누적 탑재하며 확장됩니다.

| 페이즈 (Phase) | 핵심 제품 명칭 | 진화 목적 및 통합 가드레일 (Safety Armor) |
| :--- | :--- | :--- |
| **Phase 1** | **MVP 제품 구동** | 비정형 마크다운 문자열에서 정적 토큰 및 닉네임별 유저 발화를 정밀 분리해내는 최소 기능 제품 |
| **Phase 2** | **샘플 데이터 연동** | 정적 가상 샘플 데이터셋 연동을 통해 목표 키워드의 실전 발견 여부를 추적하고 유닛 테스트 방어선 구축 |
| **Phase 3** | **데이터셋 자동 양산** | 페르소나 메타데이터 에이전트를 가동하여 수백 종의 합성 마크다운 덤프 자산을 디스크에 자동으로 찍어내는 자산 팩토리 구성 |
| **Phase 4** | **CI 자동화 검증** | GitHub Actions 런타임을 활용해 대량 생산된 자산들의 서식 깨짐이나 타입 붕괴를 빌드 타임에 전수 검사하는 오렌지 가드레일 |
| **Phase 5** | **원격 CD 및 운영 풀** | Supabase Edge 무인 배포를 완결하고, 운영 폴더 깃 푸시 웹훅 감지를 통해 실시간 라이브 유저 데이터를 격리 적재 |
| **Phase 6** | **장애 격리 서킷 브레이커** | AI API 통신 지연이 5초를 초과하면 회로를 즉시 차단하고 브라우저 로컬 `IndexedDB` 임시 대피소로 분기해 유실률 0% 달성 |
| **Phase 7** | **무중단 리스크 통제** | 실운영 에러 발생 시 데이터베이스 Config 토글 관리 장치를 통해 코드 재배포 없이 특정 컴포넌트를 무다운타임 긴급 진화 |
| **Phase 8** | **안전 거버넌스 롤백** | 8초 데드라인 타이머 복구 트랜잭션 수립 및 무다운타임 프롬프트 블루/그린 원격 배포 거버넌스를 완결하는 최종 수호 레이어 |

## 🚨 3. 삼중 운영 리스크 대응 매트릭스 (Operational Mitigation)

*   **네트워크 단절 및 API 마비 리스크 (Green Armor):** 회로 차단기가 외부 커넥션을 물리적으로 분리한 뒤, 클라이언트 로컬 영속 스토리지 트랜잭션으로 유저의 마크다운 텍스트 원본 자산을 1글자의 누수도 없이 완전히 포획 및 보존합니다.
*   **컴포넌트 데이터 오염 리스크 (Yellow Armor):** 실시간 인메모리 캐싱 레이어가 결합된 원격 피처 플래그 통제 장치가 가동되어, 전체 유저의 서비스 환경에 어떠한 로드 부하도 주지 않고 단 30초 내에 특정 장애 컴포넌트 렌더링 라인을 일반 복구 뷰로 전환시킵니다.
*   **트랜잭션 충돌 및 타임아웃 리스크 (Blue Armor):** 백엔드 처리 경로에 엄격한 8초 커트오프(Cut-off) 타임아웃 가드를 배치하고, 유효성 검증 실패 시 PostgreSQL RPC 격리 블록이 발동하여 데이터베이스의 전체 상태를 오염 이전의 무결한 마크다운 원본 스냅샷 상태로 즉각 롤백시킵니다.
