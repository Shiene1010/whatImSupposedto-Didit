# 🤖 AI PRESCRIPTION SCHEMA
> **목표 문맥을 4단계 처방으로 구조화하는 AI 출력 명세서**

본 문서는 사용자의 비정형 마크다운 목표와 대화 로그를 분석해, 완벽주의 성향 유저에게 가장 적합한 4단 처방전으로 재작성하는 AI 출력 형식을 정의합니다. 프로젝트의 핵심 목표는 단순히 문장을 요약하는 것이 아니라, 사용자가 실제 행동으로 옮길 수 있도록 "원문 → 5세 치트키 → 소리/감각 → 실행 전환" 흐름으로 가공하는 것입니다.

---

## 1. 설계 철학

사용자가 제출한 목표는 종종 추상적이고, 감정적이고, 완벽주의적입니다. 예를 들어 다음과 같은 문구가 있을 수 있습니다.

```md
> 매일 영어 회화 한 문장 완벽하게 외우기
- [ ] 저녁에 복습 로그 남기기
```

이 문장은 단순한 할 일처럼 보이지만 실제로는 다음의 의미를 담고 있습니다.

- 핵심 행동 의도: 영어 회화 문장 암기
- 심리적 압박: 완벽한 수행을 요구함
- 행동 경계: 언제, 어떻게, 얼마나 반복할지 불명확

따라서 AI는 이 정보를 아래 4단 구조로 변환해야 합니다.

1. 원문 유지
2. 5세 치트키 버전으로 단순화
3. 소리/감각 기반 명확화
4. 즉시 실행 가능한 행동 문장 생성

---

## 2. 4단 처방전 구조

AI는 최종 결과를 구조화된 JSON 형태로 반환해야 하며, 각 단계는 다음 의미를 담아야 합니다.

```ts
export interface AiPrescriptionSchema {
  userId?: string;
  personaId?: string;
  sourceType: 'target' | 'script' | 'combined';
  originalText: string;
  simplifiedText: string;
  cheatCodeText: string;
  sensoryText: string;
  actionPlan: string[];
  confidence: number;
  generatedAt: string;
}
```

### 2-1. originalText
- 사용자의 원문 목표 또는 대화 스크립트에서 추출된 핵심 문장
- 의미 변형 없이 유지
- 완벽주의 문장도 그대로 남겨야 함

### 2-2. simplifiedText
- 원문을 더 읽기 쉽게 정리한 문장
- 과도한 상투어나 감정적 긴장 완화
- 짧고 명확한 문장으로 압축

### 2-3. cheatCodeText
- 5세 수준의 단순화 버전
- "하나만 해도 됨", "오늘은 1문장만", "완료 체크만 해도 통과" 같은 경량화 표현
- 완벽주의를 완화하는 핵심 문구

### 2-4. sensoryText
- 소리, 감각, 리듬, 행동 단서로 변환
- "한 문장 말해보기", "한 번 크게 읽기", "목소리로 3번 반복하기" 와 같은 구체적 실행 방식
- 뇌가 즉시 행동으로 전환하도록 돕는 문장

### 2-5. actionPlan
- 실전 행동 목록
- 3~5개 항목으로 구성
- 각 항목은 독립적으로 수행 가능해야 함

### 2-6. confidence
- AI가 생각하는 문맥 적합도
- 0~1 범위 또는 0~100 범위 중 프로젝트 지정 값 사용
- 목표 문맥과 사용자 성향이 얼마나 잘 맞는지 나타냄

## 3. 예시 출력

아래는 실제로 자주 발생하는 목표 문맥의 예시입니다.

```json
{
  "userId": "user_001",
  "personaId": "easy_peasy",
  "sourceType": "target",
  "originalText": "매일 영어 회화 한 문장 완벽하게 외우기",
  "simplifiedText": "매일 영어 문장 하나를 암기해보세요.",
  "cheatCodeText": "오늘은 한 문장만! 완벽하지 않아도 괜찮아요.",
  "sensoryText": "작게라도 한 번 크게 읽고, 입으로 따라 말해보면 됩니다.",
  "actionPlan": [
    "오늘 영어 문장 1개를 고른다",
    "크게 소리 내서 3번 읽는다",
    "한 문장으로 의미를 말해본다",
    "완료 로그를 남긴다"
  ],
  "confidence": 0.94,
  "generatedAt": "2026-10-26T09:00:00.000Z"
}
```

## 4. 생성 규칙

AI는 아래 규칙을 반드시 준수해야 합니다.

### 4-1. 원문 손상 금지
- 사용자의 원문 목표는 왜곡하거나 삭제하지 않는다.
- 동일한 의미를 유지하면서만 압축한다.

### 4-2. 완벽주의를 부드럽게 완화
- "완벽하게", "절대", "무조건" 같은 표현은 대체로 치트키 단계에서 완화한다.
- 성취를 방해하는 문장은 실행 가능한 문장으로 재구성한다.

### 4-3. 행동 중심으로 변환
- 단순 서술형 문장은 actionPlan으로 분해한다.
- 행위를 바로 할 수 있는 형태로 작성한다.

### 4-4. 사용자 페르소나 반영
- 페르소나별 톤이 다르다.
- 예: 완벽주의형은 덜 압박스럽고 더 작게 성공하는 버전의 처방을 선호한다.

---

## 5. 검증 기준

AI 출력이 올바르게 생성되었는지 확인하는 기준은 다음과 같습니다.

- originalText는 원문을 잃지 않아야 함
- simplifiedText는 읽기 쉬운 형식이어야 함
- cheatCodeText는 즉시 실행 가능한 단순 표현이어야 함
- sensoryText는 행동이 눈에 보이도록 설계되어야 함
- actionPlan은 3개 이상, 최대 5개 이내로 구조화되어야 함
- confidence 값은 0~1 또는 0~100 범위로 정규화되어야 함

## 7. 정리

AI 처방 스키마는 단순한 텍스트 변환 문서가 아니라, 사용자의 심리적 완벽주의를 점진적으로 완화하고 실천 가능한 행동으로 전환시키는 설계 규약입니다. 이 구조를 통해 프로젝트는 단순히 "목표를 파악하는 도구"가 아니라, "행동으로 끌어내는 처방 엔진"으로 발전합니다.
