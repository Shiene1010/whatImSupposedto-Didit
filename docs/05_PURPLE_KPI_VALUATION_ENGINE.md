# 🟣 PURPLE KPI VALUATION ENGINE
> **비정형 유저 발화 대조 기반 단 한 번의 실전 성취 판정 알고리즘 명세서**

본 문서는 완벽주의 성향을 가진 사용자들이 계획의 부하로 무너지지 않도록 설계된 핵심 지표 시스템인 **🟣 Purple KPI(퍼플 지표) 판정 엔진**의 기술적 설계 구조와 키워드 매칭 매커니즘을 정의합니다.

---

## 🎯 1. 퍼플 KPI 설계 철학 (Philosophy)

*   **정량적 완벽주의의 해체:** 기존 생산성 도구들은 일주일 중 7일을 모두 달성해야 성공으로 처리하는 '올 오어 나싱(All-or-Nothing)' 방식을 채택합니다. 이는 완벽주의 유저들에게 가혹한 좌절감을 유도합니다.
*   **단 한 번의 시도 통착 (Single-Hit Success):** 퍼플 KPI는 대화 덤프 스트림 속에서 사용자가 목표 행동을 시도하거나 뱉은 기록이 **단 한 번이라도 완벽히 발견(Substring/Regex Match)**되면 해당 주차의 실전 성취 로그를 `true`로 최종 판정합니다.

---

## ⚙️ 2. 데이터 흐름 및 스캔 매커니즘 (Scanning Mechanism)

`purpleKpiEngine.ts` 모듈은 입력받은 파싱 데이터를 기반으로 아래의 3단계 가드레일 알고리즘을 수행합니다.

```text
[입력 데이터 추출] ➜ 1차 토큰 해석 (목표 내 2글자 이상 핵심 키워드 분리 및 중복 제거)
                         │
                         ▼
[실전 발화 대조]   ➜ 2차 Substring 패턴 스캔 (유저 발화 데이터 내 키워드 포함 여부 검증)
                         │
                         ▼
[행동 트리거 보정] ➜ 3차 형태소 가드 스캔 (키워드가 유실됐더라도 '완료', '했음' 등 실행 토큰 발견 시 보정)
                         │
                         ▼
[최종 리포트 산출] ➜ 성취 여부(isAchieved: true/false) 및 최종 기여도 산출 완료
```

### 1단계: 목표 키워드 풀(Pool) 정제
마크다운 파서로부터 추출된 `quotes`와 `todoItems` 텍스트를 공백 기반으로 분리하고, 언어적 노이즈를 차단하기 위해 **2글자 이상의 핵심 형태소 토큰**만 추려내어 대소문자를 정규화한 고유 집합(Unique Set)을 빌드합니다.

### 2단계: 서브스트링(Substring) 정밀 매칭
추출된 고유 키워드 루프를 가동하여, 유저가 단톡방에 뱉은 실전 발화 본문 내에 해당 키워드가 포함되어 있는지 1차 스캔을 수행합니다. 포함이 확인되면 그 즉시 매칭 카운트를 올리고 사유(`reason`)를 박제합니다.

### 3단계: 강제 행동 트리거 보정 규칙
완벽주의 유저들의 방어적 말투 특성상 목표 단어를 의도적으로 생략하고 결과만 통보할 수 있습니다. 이를 방어하기 위해 키워드 매칭이 실패했더라도 발화 내에 **실전 트리거 표기 기호**가 발견되면 성취로 긴급 보정합니다.
*   **강제 감지 트리거 화이트리스트:** `['완료', '했습', '읽었', '포기 안', '성공']`

## 📊 3. 출력 리포트 데이터 스키마 (Output Report Schema)

엔진이 판정을 완료하면 시스템 데이터베이스(Supabase) 및 프론트엔드 대시보드 레이어에 다음 구조의 규격화된 JSON 객체를 반환합니다.

```typescript
export interface KpiMatchReport {
  userNickname: string;         // 판정 대상 유저 식별자
  isAchieved: boolean;          // 단 한 번이라도 실전 성취 판정을 받아냈는가 (Core Indicator)
  matchedSpeeches: {            // 매칭이 결정된 결정적 증거 발화 로그 배열
    lineNumber: number;         // 원본 대화록 파일 내의 실제 행 번호 (1-based)
    matchedText: string;        // 매칭된 유저의 실전 발화 원문
    reason: string;             // 판정 엔진이 채택한 매칭 사유 가이드라인
  }[];
  achievementRate: number;      // 유저가 뱉은 전체 발화 수 대비 매칭된 성취 발화의 기여 비율 (%)
  evaluatedAt: string;          // ISO 8601 형식의 시스템 판정 타임스탬프
}
```

## 🧪 4. 회귀 검증 정책 (Regression Testing Policy)

*   **스냅샷 고정 규칙:** `tests/purple.test.ts` 파일은 본 엔진의 출력 필드명과 데이터 타입의 변조를 막기 위해 구조적 스냅샷 어설션을 강제 집행합니다.
*   **무결성 유지:** 외부 텍스트 전처리 라이브러리를 추가하거나 엔진을 리팩토링할 때, 본 문서에 기술된 `isAchieved` 산출 공식이 변하여 기존 유저의 과거 성취 로그가 왜곡되지 않도록 무조건적인 하위 호환성을 보장해야 합니다.
