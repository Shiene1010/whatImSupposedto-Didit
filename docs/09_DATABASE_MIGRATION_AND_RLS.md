# 📂 DATABASE MIGRATION AND RLS
> **PostgreSQL 테이블 스키마 설계 및 동료 표현 합법적 스틸(Steal) 보안 격리 정책**

본 문서는 구조화된 마크다운 데이터가 적재되는 데이터베이스(PostgreSQL)의 핵심 물리 스키마 마이그레이션 명세와, 동료 유저의 훌륭한 행동 표현 및 4단 처방전을 내 보관함으로 퍼올 수 있도록 안전하게 권한을 격리하는 **Row Level Security(RLS, 행 단위 보안) 가드레일**을 정의합니다.

---

## 🗄️ 1. 프로덕션 데이터 마이그레이션 스펙 (Schema Specification)

본 인프라는 Supabase 환경의 관계형 데이터베이스 모델을 기반으로 하며, 데이터 원자성(Atomicity)과 유저 매핑 무결성을 수호하기 위해 설계되었습니다.

### 📄 user_profiles (유저 프로필 마스터 테이블)
*   **id (UUID):** `auth.users` 기본 인증 테이블을 외래키로 참조(`REFERENCES auth.users ON DELETE CASCADE`)하는 고유 식별자. Primary Key.
*   **nickname (TEXT):** 실전 대화록 파싱 및 매칭 시 유저를 고정 추적하기 위한 유니크 필드. `NOT NULL UNIQUE`.
*   **persona_type (TEXT):** 유저 고유의 인지 장벽 성향 식별자 (`easy_peasy`, `new_year_hero` 등).

### 📄 prescription_logs (4단 처방 및 표현 적재 테이블)
*   **id (BIGINT):** 자동 증가형 고유 로그 번호. `GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
*   **user_id (UUID):** 해당 처방을 소유한 유저 프로필 매핑 외래키.
*   **original_target / five_year_old_version / cheat_key_action / phonics_sound (TEXT):** 마크다운 정적 파서와 GPT-4o 인텔리전스 엔진을 관통하여 조제된 고정 4단 처방전 데이터 필드.
*   **is_stolen_from_peer (BOOLEAN):** 동료 유저의 표현을 합법적으로 스틸(Steal)하여 복제해 온 데이터 행인지 판별하는 추적 방어용 플래그.
*   **source_log_id (BIGINT):** 어떤 동료의 원본 데이터 행에서 복제/스틸해 왔는지 꼬리를 추적하는 출처 식별 외래키. `REFERENCES public.prescription_logs(id) ON DELETE SET NULL`.

## 🛡️ 2. Row Level Security (RLS) 보안 격리 정책

멀티 테넌시 환경에서 타인의 마이그레이션 데이터를 조작하려는 악성 쿼리 인젝션을 완벽 차단하고, **'합법적 표현 스틸(Steal)'** 기능을 아키텍처 레벨에서 안전하게 구현하기 위해 설계된 행 단위 가드레일입니다.

```text
[인증된 유저의 외부 데이터 접근 요청]
       │
       ├─► 1. SELECT (조회)  ──► [보안 허용 (True)] 전체 유저는 동료의 처방전을 자유롭게 조회 및 영감 획득 가능
       │
       ├─► 2. INSERT (스틸)  ──► [보안 검증 (uid 강제)] 타인의 표현을 복제하여 오직 '본인의 명의(user_id)'로만 삽입 가능
       │
       └─► 3. UPDATE/DELETE ──► [철저 격리] 타인의 행은 절대 수정/삭제 불가. 오직 본인 소유의 행만 제어권 인정
```

### 🔐 실전 수립 RLS 가드레일 정책 코드 (Policy Summary)
1.  **전체 읽기 권한 상시 개방 정책 (`FOR SELECT`):** 
    동료 표현 스틸 기능의 전제 조건입니다. 모든 인증된 사용자(`TO authenticated`)는 타인의 처방 로그 행을 자유롭게 조회할 수 있어, 커뮤니티 전반의 실행 동기부여 자산을 공유받습니다.
2.  **명의 도용 원천 차단 정책 (`FOR INSERT`):**
    데이터 삽입은 오직 본인의 인증 토큰 ID 명의로만 수행할 수 있도록 강제 차단 제어합니다. `WITH CHECK (auth.uid() = user_id)`.
3.  **데이터 오염 무력화 격리 정책 (`FOR UPDATE / DELETE`):**
    타인의 데이터 행을 강제로 덮어쓰거나 지우려는 악성 요청을 물리적으로 무력화합니다. 오직 `auth.uid() = user_id` 조건이 참인 소유주 행에 대해서만 트랜잭션 수정을 허가합니다.

## 🧪 3. 인프라 보안 신뢰성 검증 결과 (Attack Sandbox)

*   **악성 인젝션 덮어쓰기 공격 시나리오:** 악성 해커 유저가 정상 유저의 `prescription_logs` 데이터 행 내 `phonics_sound` 필드를 가짜 에러 코드로 강제 변조하는 쿼리를 날릴 시, RLS 보안 장벽이 활성화되어 실제 데이터베이스 레이어에서 `UPDATE 0` 처리(0개 행 변경)를 즉각 집행하며 공격을 완벽 무효화합니다.
