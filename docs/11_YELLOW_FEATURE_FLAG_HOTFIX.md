# 🟡 YELLOW FEATURE FLAG HOTFIX
> **원격 Config 데이터베이스 스위치 기반 무다운타임 실시간 핫픽스 및 기능 통제 런북**

본 문서는 운영 서버 환경에서 특정 페르소나의 비정형 파서 엔진이나 처방전 출력 뷰 컴포넌트에 예기치 못한 비정형 기호 깨짐, 문법 파괴 런타임 리스크가 리포트되었을 때, 전체 서비스를 종료하거나 코드를 다시 빌드하여 CI/CD 배포 파이프라인을 태우는 시간적 다운타임 없이 단 한 줄의 데이터베이스 스위칭으로 문제를 즉각 진화하는 **🟡 옐로우(Yellow) 리스크 통제 인프라**의 운용 매뉴얼을 정의합니다.

---

## ⚡ 1. 인메모리 캐싱 피처 플래그 엔진 (FeatureFlagEngine)

`FeatureFlagEngine.ts` 모듈은 원격 Supabase Config 테이블의 켜짐/꺼짐 상태 값을 동적으로 읽어오되, 실시간 트래픽 환경에서 데이터베이스에 가해지는 무차별적인 조회(Select) 쿼리 병목과 인프라 커넥션 폭탄을 차단하기 위해 **TTL(Time-To-Live) 기반의 인메모리 가드 가이드라인**을 적용했습니다.

### ⚙️ 캐시 가드 및 핫픽스 작동 메커니즘
*   **30초 TTL 인메모리 캐시 장착:** 시스템은 원격 설정을 한 번 로드하면 내부 `Map` 구조체에 유효 상태를 기록하고 30초 동안은 DB 커넥션을 거치지 않고 메모리에서 즉각 스위치 판정을 내립니다.
*   **네트워크 단절 대비 Fallback 세팅:** 외부 인프라 통신 장해로 인해 피처 플래그 테이블 조회 자체가 불가능할 경우, 시스템 크래시를 원천 방어하기 위해 사전에 약속된 `defaultValue = true` 상태를 강제 주입하여 서비스 가용성을 사수합니다.

## 🕹️ 2. 실시간 컴포넌트 우회 게이트웨이 (ToggleGateway)

원격 설정 테이블의 플래그가 `false`(차단 상태)로 뒤집히는 순간, 프론트엔드와 백엔드의 런타임 분기 가드레일인 `ToggleGateway.ts`가 작동하여 즉각적인 기능 격리 및 복구 포맷팅을 집행합니다.

### 🧩 실전 운용 컴포넌트 렌더링 스위칭 매트릭스

| 피처 고유 키 (Feature Key) | 정상 상태 (True) 런타임 경로 | 리스크 감지 (False) 핫픽스 우회 경로 |
| :--- | :--- | :--- |
| **`enable-rina-parser`** | 리나 페르소나 전용 극단적 방어 텍스트 분리 알고리즘 가동 | 리나 컴포넌트를 즉각 격리하고 범용 `mdStaticParser` 코어 엔진으로 안전 이관(Safe Migration) |
| **`enable-phonics-hyphen-component`** | 음절 간 하이픈 기호가 노출되는 스타일리시 사운드 칩 인터랙션 뷰 활성화 | 하이픈 깨짐 오염 차단을 위해 기호를 공백으로 강제 변환 후 일반 플레인 텍스트 모드로 우회 렌더링 |

## 📑 3. 실운영 리스크 대응 긴급 진화 프로토콜 (Emergency Runbook)

실시간 운영 중 사용자 인터페이스(UI)나 특정 페르소나 엔진의 파괴 현상이 긴급 리포트되었을 때, 운영 관리자가 집행해야 하는 무다운타임 긴급 진화 3단계 프로토콜입니다.

### 1단계: Supabase 원격 운영 콘솔 SQL 샌드박스 진입
문제가 보고된 기능의 식별 고유 키를 확인한 후, 데이터베이스의 설정 행을 즉시 거짓(`false`) 상태로 업데이트하는 차단 스크립트를 즉각 실행합니다.
```sql
-- 예시: 포닉스 하이픈 컴포넌트의 가동을 무조건 물리적으로 즉각 긴급 중단
UPDATE public.system_feature_flags 
SET is_enabled = false, 
    updated_at = TIMEZONE('utc'::text, NOW())
WHERE key = 'enable-phonics-hyphen-component';
```

### 2단계: 인메모리 캐시 강제 퍼지 (Optional Quick Purge)
최대 30초의 TTL 대기 시간조차 허용되지 않는 초긴급 크래시 리스크 상황일 경우, 운영자는 관리자 백엔드 API 인터페이스를 통해 피처 플래그 엔진의 `clearCache()` 메서드를 즉각 원격 강제 호출하여 서버 내부 인메모리 스위치 메모리를 완전 초기화(Purge)시킵니다.

### 3단계: 라이브 무다운타임 우회 결과 모니터링
원격 스위칭 배포가 완료되면, 서버 재기동 없이 라이브 유저들의 화면에서 에러 컴포넌트가 완전 격리되고 안전한 대체 복구 뷰(Fallback Plain Text)로 실시간 복구 전환되었는지 로그 스트림을 최종 확인합니다.
