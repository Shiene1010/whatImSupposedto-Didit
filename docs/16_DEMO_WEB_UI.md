# 데모 웹 UI

## 데모 목적

목표 Markdown, 화자별 대화록, 대상 닉네임을 입력해 작은 실행 신호와 다음 행동을 확인합니다. 목표 파싱, 발화 분리, 규칙 신호 평가는 기존 `parseMarkdown`, `splitScriptByUser`, `evaluatePurpleKpi`를 브라우저에서 실행합니다.

## 사용 방법

1. `예시로 바로 체험`을 눌러 다중 화자 샘플과 `EasyPeasy` 닉네임을 불러오거나, 목표 Markdown·화자별 대화록·대상 닉네임을 직접 입력합니다.
2. `오늘의 작은 성취 찾기`를 누르면 파싱된 quote/checklist, 선택된 화자의 발화, 규칙 기반 데모 처방과 match 근거가 표시됩니다.
3. 결과는 “달성률”이 아니라 추출된 대상 발화 중 규칙에 일치한 발화의 수입니다. 키워드/트리거 신호는 의미 이해나 실제 행동 완료를 증명하지 않습니다.
4. 목표, 대화록, 닉네임을 수정하면 이전 분석은 초기화됩니다. 새 입력으로 다시 분석해야 합니다.

## 개인정보와 생성 방식

- 입력값은 React 화면 상태에서만 사용되며 API나 데이터베이스로 전송하거나 저장하지 않습니다.
- 처방 문구는 데모용 템플릿이며 OpenAI 등 외부 AI 호출을 하지 않습니다.
- 화자 발화는 `**nickname**:`, `[nickname]:`, `nickname:` 형식으로 분리하며 원본 대화록을 대상 화자로 임의 변환하지 않습니다.
- 처방 영역에 규칙 기반 데모임을 표시하고, 결과 하단에 실제 KPI 사용과 템플릿 생성 사실을 안내합니다.
- 게스트로 계속 체험할 수 있으며, Google 로그인은 계정 식별/로그아웃을 위한 선택 기능입니다.
- 전용 시연 테스트 계정에만 네 개 페르소나 샘플 전환기가 표시됩니다. 프로필 전환은 브라우저에서 예시 입력을 바꿀 뿐이며, 사용자 입력이나 프로필 설정을 서버에 저장하지 않습니다.
- 허용된 Google 테스트 계정은 최초 로그인 완료 시 3일 이용권을 자동으로 받습니다. 서버의 `DEMO_TEST_ACCOUNT_EMAIL`과 일치하고 Google 이메일 인증이 된 계정만 이용할 수 있습니다. 계정·이용권 데이터는 해당 Supabase 사용자 UUID 기준으로 관리되며 같은 이메일로 재가입하면 새 계정에 이용권을 다시 지급합니다.
- 테스트 계정에만 **모의 구독 시작 및 즉시 취소**가 표시됩니다. 모의 결제 이벤트 금액은 0원이며 실제 결제·자동 갱신·청구는 발생하지 않습니다. Toss 결제 연동은 보류 상태입니다.
- 테스트 계정 탈퇴는 두 번 확인을 받고 해당 사용자의 테스트 기록과 처방 기록을 삭제한 뒤 Supabase Auth 계정을 삭제합니다. 다른 사용자 계정이나 데이터는 대상이 아닙니다. 탈퇴 뒤 같은 Google 이메일로 재가입해 로그인 흐름을 다시 시험할 수 있습니다.

## 실행 및 배포

로컬 실행은 `npm run dev`, 검증은 `npm test -- --runInBand` 및 `npm run build`를 사용합니다. 서버에 `DEMO_TEST_ACCOUNT_EMAIL`, `SUPABASE_SERVICE_ROLE_KEY`를 설정해야 합니다. 실제 Google 이메일 주소나 서비스 키를 코드/채팅에 넣지 마세요. 새 DB에는 `database/migrations/`의 시연 계정 관련 마이그레이션을 타임스탬프 순으로 적용합니다. 마지막 lifecycle migration은 기존 시연 구독 테이블도 참조합니다.

프로젝트의 기존 Vercel 배포 연결을 통해 기본 브랜치 변경 후 배포할 수 있습니다. 배포 활성화 전 새 마이그레이션과 서버 환경변수 설정이 필요합니다.
